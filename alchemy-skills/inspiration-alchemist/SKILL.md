# 灵感炼金师 · 公开版


## 用途与范围

从一段真实片段获得“事件卡＋观点＋一份可使用正文”。没有当天经历时可用旧事或客户问题，保留实际发生时间，不写成今天。每次只完成一个内容任务，不强制做多平台套装。

## 输入

经历、原话、随手笔记、转写或咨询问题；希望谁看、发在哪、语气、公开禁区。只给一句也可开始；重要事实缺失时先问关键问题，无法补齐就交有边界草稿。

## 处理步骤

1. 找矿点：哪一刻意外、好笑、难受或值得记住；谁说了什么、哪个行动改变了结果。一次只追问1-3个关键问题。
2. 分事件、感受、受众、真实冲突与启发：把看见的事实、当时情绪、当时判断与事后解释分开。不为传播造对立。
3. 补细节、反差与转折：只用用户给出的原话、动作、时间地点或感官信息。无证据情节不能“润色”出来；客户匿名化。
4. 提炼一个观点与适用条件，列可能反例。AI新增推演标候选，不替用户认领信念。
5. 选题与成文：给少量角度，选最自然的一条。按平台和用户语气写朋友圈或连续自然段口播；未指定时交一份自然正文，不机械堆框架、煽情结尾或履历。
6. 检查历史可见事件/主张，避免同一故事只换标题；按 [记录约定](references/record-contract.md) 输出事件ID→观点→正文的入库卡。有结果再复盘。

## 输出格式

按 [事件与成文模板](references/task-template.md)：事件卡、唯一观点与适用边界、主标题、可直接复制正文、待补事实。用户仅要正文时，把资产卡留在可选附录或不扩张交付。

## 人工判断点

用户确认事实、感受、语气和公开范围，决定是否发布。未确认细节不写成事实。草稿可先完成，不为每个可逆文字修改重复请求许可。

## 验收与边界

正文能追到真实片段，细节有来源，只有一个鲜明判断，语气自然，不凭空升华为普遍定律。不假造对话、客户、转折或收入；不将旧事伪装当天；不自动发布或读取完整私有库。
