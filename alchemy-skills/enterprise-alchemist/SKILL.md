# 企业炼金师 · 公开版


## 用途与范围

公开版完成一个业务问题的初诊：诊断清单、证据缺口和可审阅验证草案。采用工具层→知识层→流程层→组织层的检查框架；这是分析框架，不是已实证成熟度标准。以经营结果验收，不以Agent数量验收。不预设有驻场观察、数据库权限或可计算ROI。

## 输入

部门/业务、一个当前问题、任务输入输出、频率与大致耗时、现有做法、期望结果。缺基线或负责人时仍可做初诊，但相关字段标待补。用户只问工具推荐时只回答工具问题。

## 处理步骤

1. 把愿望改成具体问题：谁在什么场景，哪一步发生什么损失。区分观察、用户自述与AI假设。
2. 找钱路：收入、成本、质量、周转或风险，选择能衡量的一项。未知成本不编金额，省时不直接等于利润。
3. 拆一个任务：触发→输入→判断→动作→输出→验收→例外，先问能否取消或简化步骤。
4. 按四层列证据/缺口：工具是否能完成任务；知识是否有业务定义和真实样本；流程是否有交接/异常兜底；组织是否有负责人/权限/持续维护。简单任务只改善必要层。
5. 给最小验证草案：选边界清楚、风险可控的任务，拟定样本、原方式基线、成功/停止条件、人工接管和复盘口径。阈值只能来自业务容忍度或标拟定，不随意填百分比。
6. 按 [输入与回流约定](references/record-contract.md) 输出未知与后续补证。没有实施数据只交方案，不报已实现ROI。

## 输出格式

按 [初诊模板与示例](references/task-template.md)：一个问题卡、四层清单、最关键证据缺口、一个验证草案、负责人/权限/接管待确认项。

## 人工判断点

业务负责人确认问题、指标与容忍度；领域人员确认判断与异常；数据所有者确认权限；负责人决定试点执行。草稿可先完成，不能把初诊当现场调查结论。

## 验收与边界

问题具体，四层有证据或缺口，试点能照草案补齐条件，异常与接管明确；不虚构现场、企业结果、营收、权限或替代员工数量。复杂多部门落地需要真实现场与授权资源，本小任务不承诺自动完成。
