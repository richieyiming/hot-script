# 热点、个人资产与去重闭环 · 公开版

## 使用

找热点、跟爆款和新稿/复盘时读取，普通语句润色不重走选题。沿用原入口交付与合规，用户资料来自用户本次提供或授权来源，不加载作者个人档案。

## 输入与处理

输入：热点/案例、真实观点/经历、目标人群、真实供给、历史选题。
1. 推荐前查已选、已做、已发布三种状态，按事件/人物/产品/核心主张及近义表达去重。缺历史资料说明检查范围。已推荐未选只是候选；换标题不算新题。用户明确重做或有可核验新进展时保留旧ID并注明续篇/重做。
2. 原热点时间窗口继续24-72小时；AI赚钱案例优先实际新进展近30天，最多90天，并核对发生日与报道日。人物/产品/变现路径/金额性质/周期/来源清楚才叫有收入证据；本人披露和第三方估算分开，不用融资估值冒充收入，缺合格样本如实说明。
3. 匹配1-3条用户自己的资产：观点、方法或真实案例有一个真实连接即可。没有连接不硬蹭，不捏造亲历。公开通用版不要求每个行业都强加AI赚钱案例。
4. 确定人群和实际困惑，从事实中提炼冲突/破立，写事实→用户判断→行动；无冲突时不硬造。用户观点、外部事实和AI推演分开。
5. 商业承接选无CTA、提问/动作、真实资料或Skill、咨询/服务之一，依据需求阶段与供给准备；不存在的产品不设计假入口，不自动引用旧价格。
6. 成文仍像真人聊天，一条一个判断。时长按本次用户要求，未要求时讲清必要事实即可；成稿估算不反向删关键因果。

## 输出、人工与验收

新增研究侧记录：asset_id / 来源 / 条件 / 核心判断 / 承接理由 / 去重范围。默认成品仍为标题＋正文＋必要来源，不为内部记录强加完整交付包。用户确认自身观点与隐私、决定发布；验收增加三状态去重、可反查资产、真实承接和原交付完整。

## 回流

账本字段：id/account/platform/event_key/claim/source/status/output_path/selected_at/produced_at/published_at；未知时间null。实际发布后记录曝光、互动、有效咨询、成交、时间窗、样本与口径；区分传播、需求和商业效果。评论新问题进需求，未成交回产品，交付结果进案例。无数据不编复盘，不自动发布。
